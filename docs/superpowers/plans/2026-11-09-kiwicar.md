# KiwiCar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Un'app Android nativa per registrare rifornimenti di benzina e rabbocchi d'olio e vedere consumi e costi medi, con dati salvati in locale.

**Architecture:** App a modulo singolo, pattern MVVM. Room (SQLite) per gli inserimenti, DataStore per auto e prezzi. Un `KiwiRepository` espone gli inserimenti arricchiti col consumo calcolato (logica pura in `domain/Calculations.kt`). UI in Jetpack Compose (Material 3) con navigazione a 4 tab. La logica dei calcoli è testata su JVM; le schermate si verificano con build + controllo visivo.

**Tech Stack:** Kotlin, Jetpack Compose (Material 3), Room, DataStore Preferences, Kotlin Coroutines/Flow, JUnit4 (+ Robolectric per i test del DAO). Build con Gradle (Kotlin DSL).

**Spec:** `docs/superpowers/specs/2026-11-09-kiwicar-design.md`

## Global Constraints

- Lingua UI: **italiano**; numeri in **formato italiano** (virgola decimale, es. `6,8`).
- Funzionamento **offline**; dati **solo in locale** sul dispositivo (nessun account/cloud/rete).
- Package applicativo: `com.kiwicar`. `compileSdk` 35, `minSdk` 26, `targetSdk` 35 (floor; versioni esatte delle librerie lasciate al builder — ultime stabili).
- Una sola auto; nessun multi-auto.
- Costo **sempre** = litri × prezzo configurato; l'importo reale non si inserisce né si memorizza.
- Tema **scuro**; accento verde `#2E7D32` / `#66BB6A`, olio `#FFB74D`. **Icone minimali a linea** in tutta l'app. **Titoli delle sezioni di raggruppamento in GRASSETTO MAIUSCOLO** in tutta l'app. Tab attivo = pillola verde con icona + testo; altri tab = sola icona.

## Review Focus

- **Primo inserimento di un tipo** → nessun riferimento precedente: il consumo è assente (`null`) e la UI mostra `—`, non `0` né un crash. (Task 4, Task 7)
- **Due inserimenti con stesso chilometraggio** (distanza 0) → nessuna divisione per zero: consumo `null`/`—`, mai `Infinity`/`NaN`. (Task 4)
- **Inserimento con km minore di uno esistente** (fuori ordine o errore di battitura) → ordinamento/riferimento per km, nessun consumo negativo; validazione km non decrescente in inserimento. (Task 4, Task 8)
- **Storico vuoto / parziale** → Home e Grafici mostrano stato vuoto; le medie non dividono per zero mesi (mesi trascorsi ≥ 1, totale vuoto → 0). (Task 4, Task 7)
- **Modifica/eliminazione di una voce intermedia** → ricalcolo del consumo della voce successiva dello stesso tipo; eliminando l'unico riferimento, la successiva diventa "prima" (consumo `—`). (Task 5, Task 10)
